# M03-0004 — Topic naming and key partitioning

**Story:** #24  
**Status:** Decided

## Topics

| Topic | Purpose |
|---|---|
| `arfd.market_db.market_rule` | Debezium change events for `market_rule` (topic.prefix=`arfd`) |
| `arfd.schemahistory.market_rule` | Debezium schema history (internal) |

## Keys / partitioning

- **Message key:** Debezium primary key of `rule_id` (default MySqlConnector behavior).
- **Partitioning:** Single-partition is acceptable for M03 volume validation; scale later by increasing partitions while keeping key=`rule_id` so per-rule order is preserved.
- **Do not** change `topic.prefix` without a coordinated consumer redeploy.

## Out of scope

Custom SMT rekeying, multi-table fan-out (later tables get `arfd.<db>.<table>`).
